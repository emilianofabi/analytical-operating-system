# Module 10: Programming, Computational Thinking, and Applied Research Engineering

## Track
Foundational

## Credit Hours
5

## Core Purpose

Cultivate computational judgment: the ability to write clear, reproducible, testable, maintainable code that transforms ideas, data, models, and analyses into executable artifacts.

## Governing Principles

1. Code is executable reasoning.
2. Reproducibility is part of credibility.
3. Clear interfaces reduce confusion.
4. Debugging is evidence-seeking.
5. Tests encode expectations.
6. Programs should be readable by humans.
7. Notebooks are useful for exploration but insufficient for production.
8. Computational artifacts require documentation and version control.

## Core Questions

- What should the program do?
- What input does it receive?
- What output should it produce?
- What assumptions are encoded?
- What can fail?
- How will correctness be checked?
- How will someone reproduce this?
- How should the code be organized?
- What should become a function, class, script, or notebook?

## Lesson 1

### Title
Code as Executable Reasoning

### Central Problem
Programming is not merely syntax. Code expresses a sequence of assumptions, transformations, decisions, and checks. A program is credible only when its logic is readable, reproducible, and testable.

### Required Concepts

- variable
- expression
- function
- input
- output
- control flow
- data structure
- error
- test
- reproducibility

### Required Outputs

- simple Python script with clear inputs and outputs
- short explanation of assumptions encoded in the code
- oral-defense answer explaining why code that works once is not enough
